# Tasks: multivac keeps no code graph

**Input**: Design documents from `/specs/081-drop-graphers/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/cli-output.md, quickstart.md

Tests are included: every behaviour lands with a check (Constitution I, "tests ship with
behaviour"); the documents are checked by their legs, each dry-run on the tree it lands on.
Work in the change's worktree, `.multivac/worktrees/drop-graphers/brain` (`WT`); `NEW` is
`node dist/cli.js` there. The human runs every `multivac change …` command; no task runs one.

**Every figure, leg count and `file:line` here is the design's, measured on `41e52c5`/`f156896`
and on a prototype in scratch (research.md); Phase 1 re-measures them on the change's tree before
any edit, and where a line moved the task follows the text, not the number. The source is
RE-DERIVED from these tasks, never copied from the prototype.**

Rules for every task:

- **The gate judges every commit.** The pre-commit shim runs the worktree's own build
  (`node dist/cli.js verify`: this repository is multivac, MV-92), so 0.15.0's code until the
  source commit and the new build after; main's 0.15.0 `mvac verify` over `WT` is run beside it
  and must agree. Both read the working tree, not the index, so every commit is made from a tree
  whose working copy equals what it commits. A retired row's `absent` legs and every `absent`,
  `count` and `each` leg block, and so does a vacuous leg. So a tombstone, a moved blocking leg and
  a dropped leg over a deleted file change in the commit whose edit greens them — never earlier,
  never later — and every commit is made through the hooks (no `--no-verify`).
- **The change claims MV-153 and the 34 rows it amends** (SKILL.md rule 4, MV-150), so `change
  close` verifies all 35: each must end stated, anchored and ok, `present` and `unique` legs
  included.
- **MV-153's legs** land with the edit that greens each (FR-027), dry-run with `NEW count` first.
- **A rewritten file keeps every existing leg on it** at its count (research.md R13.4); a test
  whose title an existing leg reads is changed, never deleted, unless R10 drops that leg with it.
  Before deleting any test, `grep -F` its title in `.multivac/invariants.md`.
- Site pages name no law ID and no version string (MV-126, MV-84). `.claude/skills/multivac/**`,
  `AGENTS.md`, `.multivac/flow.md` are regenerated by `NEW doors`, never hand-edited (MV-72).
- **Main's checkout is never edited.** The change body is recorded in `WT`'s copy of
  .multivac/changes/drop-graphers.md (its frontmatter untouched), and reaches main with the merge.
- **Main's refresh hook rewrites `WT`'s tracked `graphify-out/graph.json`** in the background after
  every Edit or Write in `WT` while it holds one (R9): before each commit, wait for
  `WT/.multivac/cache/graph-refresh.lock` to go and `git checkout -- graphify-out/graph.json`, so no
  commit before T063 carries a rebuilt graph.
- **After T063 no file is edited with the Edit or Write tools**, in any checkout (R9).
